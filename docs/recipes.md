# Формат рецепта «Моя кухня»

JSON в UTF-8. Один рецепт — объект с `version: 1`. Пример — [плов с говядиной](../public/data/recipes/pilaf.json). [JSON Schema](../public/data/recipe.schema.json) перечисляет обязательные поля и диапазоны.

| Поле | Значение |
|---|---|
| `id` | Уникальный стабильный ID, строчные латинские буквы, цифры, дефис или подчёркивание. Начинается с буквы или цифры. |
| `name`, `description`, `category` | Название, краткое описание, категория. |
| `difficulty`, `prep`, `cook`, `servings` | Сложность 1–5, подготовка и готовка в минутах, целое количество порций. Для блюда без нагрева укажите в `cook` время сборки. |
| `image` | Пустая строка или изображение в виде `data:image/webp;base64,…`. Также поддерживаются JPEG, PNG и ссылки `dish:0`–`dish:69` на неизменяемые позиции встроенных иллюстраций. |
| `source` | Необязательный объект `{ "title": "Название источника", "url": "https://…" }` со ссылкой для сверки. |
| `ingredients` | Массив объектов с `id`, `name`, `quantity` (число), `unit`, `group` и необязательным `substitution`. ID уникальны внутри рецепта. |
| `tools` | Массив строк с инструментами и посудой. |
| `steps` | Массив шагов: `title`, `instruction`, `ingredients` (ID продуктов), `temperature`, `ready`, `parallel`, `timers` (массив объектов `{ "name": "Название", "seconds": 60 }`). Для необязательных текстов используйте пустую строку, для списков — пустой массив. |
| `tips`, `mistakes` | Массивы строк с советами и распространёнными ошибками. |

Для набора рецептов используйте объект `{"format":"moya-kuhnya-recipes","version":1,"recipes":[...]}`, где `...` заменяется объектами рецептов. Отдельный формат резервной копии `moya-kuhnya-backup` описан в [схеме обмена](../public/data/exchange.schema.json).

Версии рецепта, набора, копии и IndexedDB независимы. Рецепты и наборы используют версию 1. Копии версии 2 сохраняют покупки по блюдам. При восстановлении копии версии 1 её список переносится в общий список. Неизвестные версии отклоняются до записи в базу.

## Запрос для ChatGPT

> Подготовь рецепт «НАЗВАНИЕ» для импорта в приложение «Моя кухня». Верни только один валидный объект JSON в UTF-8, без Markdown. Поля: version (1), id (уникальный slug из строчной латиницы, цифр и дефисов), name, description, category, difficulty (целое 1–5), prep (целое число минут от 0), cook (целое число минут от 1), servings (целое 1–100), image (пустая строка), ingredients, tools, steps, tips, mistakes. ingredients — массив объектов с уникальным id в пределах рецепта (например, i1), name, quantity (положительное число, без текста), unit, group, substitution (замена, если возможна). tools — массив названий посуды. Каждый шаг содержит title, instruction, ingredients (массив ID использованных продуктов), temperature, ready, parallel и timers. Таймер — объект с name и seconds (целое от 1 до 86400). Необязательный текст шага обозначь пустой строкой, отсутствие таймеров — пустым массивом. tips и mistakes — массивы конкретных советов и ошибок. Укажи размер нарезки, нагрев, время, когда перемешивать, признаки готовности и безопасную внутреннюю температуру там, где она необходима. Количества продуктов укажи в ingredients; если надо добавить лишь часть, назови долю или порядок добавления, чтобы инструкцию можно было применять при изменении числа порций.

Сохраните ответ в файл `recipe.json` и выберите его в **Рецепты → Импорт**.

## Планируемый ZIP-пакет

Предлагаемая структура: `manifest.json` с типом и версией контейнера, `recipes.json` с набором рецептов и `images/<id>.webp`. Манифест связывает ID рецепта с путём, размером и SHA-256 изображения. Импорт должен проверять пути, количество и объём распакованных файлов и контрольные суммы до записи. В текущей версии изображения передаются внутри JSON.
