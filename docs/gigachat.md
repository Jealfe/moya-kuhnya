# GigaChat: настройки и анализ готовки

## Ввод ключа

1. Установите APK и откройте **Настройки → Искусственный интеллект**.
2. Вставьте **ключ авторизации** из кабинета GigaChat (Base64, не временный access token).
3. Укажите тип доступа: личный `GIGACHAT_API_PERS`, бизнес `GIGACHAT_API_B2B` или
   корпоративный `GIGACHAT_API_CORP` согласно вашему аккаунту.
4. Нажмите **Сохранить ключ**, затем **Проверить подключение**.
5. Проверка получает список доступных моделей. Выберите поддерживаемую модель из подсказок
   поля «Модель» и сохраните настройки. По умолчанию — `GigaChat-2`.

Поле ключа очищается после сохранения. Оставьте его пустым, если меняете только модель или тип доступа.
Сохранённый секрет не возвращается в JavaScript. **Удалить ключ** удаляет шифротекст, ключ шифрования
в Keystore и токен из памяти. Сами рецепты, дневник и рекомендации остаются.

Ключ шифруется AES-256/GCM ключом Android Keystore, шифротекст хранится в закрытых SharedPreferences.
Он исключён из системных резервных копий и переноса устройства. Ручная JSON-копия содержит
только данные IndexedDB; ключ и временный токен в неё не входят.
Клиентское хранение не даёт абсолютной защиты на скомпрометированном/root-устройстве.
Отладка WebView и логирование Capacitor отключены даже в debug APK.

## Использование

Сохраните впечатления после готовки. В дневнике появится **Разобрать ошибки с ИИ**.
Результат содержит краткий вывод, проблемы, возможные причины, рекомендации, шаги,
план следующей готовки и до двух вопросов. ИИ не редактирует рецепты и отзывы.
Возможные причины — предположения; ориентируйтесь на фактическую готовность и безопасность продуктов.

Запрос выполняется только по кнопке. Повторное открытие дневника, рецепта или результата
не вызывает GigaChat. **Повторить анализ** явно отправляет новый запрос и заменяет прежний
анализ этой попытки. При невалидном JSON, сетевой ошибке или отмене предыдущий сохранённый
результат остаётся. В процессе анализа доступна кнопка отмены.

Отправляется только выбранный рецепт: описание, ингредиенты, количество, шаги, температуры,
таймеры, текущая оценка и заметки. Для новых попыток сохраняются снимок исходного рецепта
и выбранное количество порций. Для старых записей без снимка используется текущий рецепт.
История ограничена тремя предыдущими попытками этого блюда и их анализами/отметками.
Фото, Base64-изображения, другие блюда и настройки не отправляются. При превышении 38 000
символов сначала исключаются старые попытки; чрезмерно большой одиночный рецепт отклоняется.

Для нового анализа исправлений дополните заметки очередной попытки. Отметки **Выполнено**
и **Полезно** передаются в контекст следующего анализа. Выполненные советы скрываются на шагах.
Перед повторной готовкой отображается план из последнего актуального анализа, на связанных
шагах — соответствующие советы. Старые анализы не суммируются в бесконечный список.
Если все рекомендации выполнены, старый план скрывается.

Результат связан с recipeId, entryId, временем, SHA-256 рецепта и SHA-256 отзыва.
При изменении отзыва или рецепта результат помечается потенциально устаревшим и не используется
для подсказок на шагах изменённого рецепта. Идентификаторы шагов — индексы с нуля в JSON,
в интерфейсе они показываются с единицы. Схема: `public/data/ai-result.schema.json`.

## Хранение и перенос

Анализы — отдельное поле `aiAnalyses` в существующем состоянии IndexedDB.
Схема объекта рецепта не изменена; обновление IndexedDB и очистка базы не требуются.
Старое состояние дополняется пустым списком анализов при чтении.
Формат полной копии v2 дополнен необязательными полями; импорт поддерживает прежние v1/v2.
Новые копии с анализами открывайте в обновлённой версии приложения.
В браузере отправка в GigaChat недоступна, но результаты читаются, отметки меняются и сохраняются.
Рецепты и пользовательские данные находятся внутри APK/IndexedDB и доступны без сети;
для нового анализа нужен интернет. GitHub не получает отзывы и рекомендации ИИ.

## Нативное подключение

Kotlin-модуль `GigaChat` использует Capacitor Bridge и HTTPS без сервера-посредника.
OAuth: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, RqUID UUIDv4, scope аккаунта.
API: `https://api.giga.chat/v1/`. Для JSON используется `response_format.type=json_schema`,
сама схема передаётся через `response_format.schema`, `strict=true`.
Токен хранится в памяти до `expires_at` с запасом 60 секунд, при HTTP 401 обновляется один раз.
Проверка подключения вызывает GET models; анализ — POST chat/completions.
Сетевой код работает в отдельном executor; тайм-аут подключения — 15 с, чтения — 60 с,
ответ ограничен 1 МБ. Отмена закрывает активное соединение. Доступ к сети не блокирует UI.
Редиректы отключены; ключ и токен отправляются только фиксированным официальным адресам.
Сообщения об ошибках не содержат тела ответа, ключа или заголовков авторизации.

TLS и проверка hostname включены. Дополнительный корневой сертификат разрешён только
для `api.giga.chat` и `ngw.devices.sberbank.ru`, без поддоменов. Для остальных адресов
используется системное доверие. Сертификат скачан по HTTPS из официального источника,
без `-k` и без trust-all обработчиков:

- Источник: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
- SHA-256: `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`
- Срок: 2022-03-01 — 2032-02-27.

Официальная документация, проверенная при реализации:

- [Авторизация и актуальный адрес API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)
- [Структурированный JSON](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output)
- [Сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates)

## Что проверить на телефоне

- Сохранение ключа, перезапуск приложения, проверку подключения и доступных моделей.
- Успешный живой анализ и его соответствие реальному рецепту/отзыву.
- Неверный ключ, тип доступа, отсутствие сети, тайм-аут и отмену.
- Повторное чтение результата в авиарежиме, отметки полезности и выполнения.
- Новый анализ после исправления ошибки и подсказки следующей готовки.
- Удаление ключа; восстановление JSON без восстановления ключа.
- Установку обновления поверх APK с той же подписью и сохранением данных.

Эмулятор и реальное устройство при разработке не использовались. Тесты транспорта используют
подставные ответы, браузерные проверки — имитацию Bridge. Они не заменяют проверку живого API.
